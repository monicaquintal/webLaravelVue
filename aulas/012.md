<h2 id="topico1">1. IMPORTANTE - Ajustando as configurações de acesso ao SMTP do Gmail</h2>

- na próxima aula, ao invés de utilizar a senha de acesso a conta do Gmail, fazer a geração da senha exclusiva seguindo o passo a passo a seguir.
    - atualmente a opção de "apps menos seguros" não está mais autorizada pelo Google. Agora precisamos gerar uma senha exclusiva para este fim.

- para configurar uma senha exclusiva para o projeto, acessar a conta de e-mail do Gmail que será utilizada e seguir os passos:
    - 1. Clique na opção "Gerenciar sua Conta do Google".
    - 2. Clique na opção "Segurança".
    - 3. Ative a opção de "Verificação em duas etapas".
    - 4. Clique na opção "Senhas de app".
    - 5. Clique na opção "Selecione o app e o dispositivo para o qual você quer gerar a senha de app" e escolha a opção "Outro".
    - 6. Defina um nome (pode ser qualquer nome) e depois clique em "gerar".
    - 7. A senha será gerada, basta copiá-la.
    - 8. Na próxima aula, utilize a senha copiada no passo 7 no arquivo de configuração do projeto (.env).

<h2 id="topico2">2. Configurando o envio de e-mails (Reset Password) - Parte 1</h2>

- o framework Laravel permite, de modo muito simples, que seja configurado um servidor SMTP para que, a parti5r dessa conexão, seja possível disparar emails.
- utilizaremos esse recurso para habilitar o **reset de senha**.
- precisaremos de uma conta em algum servidor SMTP, como Gmail, Outlook, Yahoo, etc.

- no `arquivo .env`:

~~~bash
MAIL_MAILER=smtp
MAIL_SCHEME=null
MAIL_HOST=smtp.gmail.com
MAIL_PORT=587
MAIL_USERNAME=cursolaravelvue123@gmail.com
MAIL_PASSWORD=SENHA
MAIL_FROM_ADDRESS="${MAIL_USERNAME}"
MAIL_FROM_NAME="${APP_NAME}"
~~~

- ajustar no BD para que um dos registros possua um email válido; clicar em "Esqueceu a senha?" e inserir o email!

<h2 id="topico3">3. Criando um template de e-mail com Markdown Mailables</h2>

- `Markdown Mailables` permitem criar modelos de emails com base em templates e componentes pré-existentes.
- executar a linha de comando "php artisan make:mail", com 3 parâmetros:
    - 1. nome da classe que controlará esse modelo de mensagem de email (nesse caso, "MensagemTesteMail")
    - 2. instrução "--markdown", indicando que vamos criar essa notificação de email utilizando recursos de markdown
    - 3. view associada à classe ("emails.mensagem-teste").

~~~bash
php artisan make:mail MensagemTesteMail --markdown emails.mensagem-teste
~~~

- em `routes/web.php`:

~~~php
Route::get('/mensagem-teste', function() {
    return new MensagemTesteMail();
});
~~~

- em `resources/views/emails/mensagem-teste.blade.php`:

~~~php
<x-mail::message>
# Introdução

O corpo da mensagem.

<x-mail::button :url="''">
Texto do botão
</x-mail::button>

Obrigada,<br>
{{ config('app.name') }}
</x-mail::message>
~~~

<h2 id="topico4">4. Enviando e-mails</h2>

- para disparar as mensagens, utilizaremos a `classe Mail`, disponível no contexto do framework Laravel; por meio dela teremos acesso a alguns métodos estáticos como to() e send().
    - `Mail::to(<destinatário>)->send(<mensagem>);`

- em `routes/web.php`:

~~~php
Route::get('/mensagem-teste', function() {
    // return new MensagemTesteMail();
    Mail::to('email@email.com')->send(new MensagemTesteMail());
    return 'E-mail enviado com sucesso!';
});
~~~

- também podemos fazer esse envio pelo Tinker:

~~~bash
use App\Mail\MensagemTesteMail;
php artisan tinker Mail::to('email@email.com')->send(new MensagemTesteMail());
~~~

- se retornar "null", é sinal que deu certo e não houve erro.

- para visualizar a alteração, modificar a rota em `routes/web.php`:

~~~php
Route::get('/mensagem-teste', function() {
    return new MensagemTesteMail();
    // Mail::to('monica.zoom@hotmail.com')->send(new MensagemTesteMail());
    // return 'E-mail enviado com sucesso!';

~~~

- também temos a possibilidade de trocar o logo (`resources/views/vendor/mail/html/header.blade.php`):

~~~php
<img src="http://localhost:8000/img/logo.png" class="logo" alt="Laravel Logo">
~~~

- outro recurso interessante é a substituição do nome da nossa aplicação, de modo que esse nome afete o footer do nosso template de email. Essa alteração é feita na **variável APP_NAME**, variável de ambiente contida no `arquivo .env`.

~~~
APP_NAME="Controle de Tarefas"
~~~

- essa alteração do APP_NAME modifica o footer no arquivo `html/footer.blade.php` em `{{ Illuminate\Mail\Markdown::parse($slot) }}`, e causará um erro na logo, pois, em `header.blade.php`: 

~~~php
@if (trim($slot) === 'Laravel')
    <img src="http://localhost:8000/img/logo.png" class="logo" alt="Laravel Logo">
@else
    {!! $slot !!}
@endif
~~~

- ou seja, ele testa o nome do app; se ele corresponder a Laravel, carregará a imagem do logo - e se não for, substituirá a imagem pelo novo nome do app (Controle de Tarefas). Para corrigir:

~~~php
@if (trim($slot) === 'Controle de Tarefas')
    <img src="http://localhost:8000/img/logo.png" class="logo" alt="Laravel Logo">
@else
    {!! $slot !!}
@endif
~~~

<h2 id="topico6">6. Configurando o envio de e-mails (Reset Password) - Parte 2</h2>

- para interceptar o fluxo de envio do e-mail de recuperação, inserir em `app/Models/User.php`:

~~~php
public function sendPasswordResetNotification($token)
{
    dd('Chegamos até aqui!');
}
~~~

- frameworl Laravel possui uma estrutura/camada de notificações (neste caso, de e-mail), que possibilita manipular as classes de email, que por sua vez vão manipular a criação das view usando o markdown mailables.
- na linha de comando, executar:

~~~bash
php artisan make:notification RedefinirSenhaNotification
~~~

- em `app/Models/User.php`:

~~~php
use App\Notifications\RedefinirSenhaNotification;
// ...
    public function sendPasswordResetNotification($token)
    {
        $this->notify(new RedefinirSenhaNotification($token, $this->email, $this->name));
    }
~~~

- em `app/Notifications/RedefinirSenhaNotification.php`:

~~~php
use Queueable;
public $token;
public $email;
public $name;

public function __construct($token, $email, $name)
{
    $this->token = $token;
    $this->email = $email;
    $this->name = $name;
}

public function toMail(object $notifiable): MailMessage
{
    $url = 'http://localhost:8000/password/reset/'.$this->token.'?email='.$this->email;
    $minutos = config('auth.passwords.'.config('auth.defaults.passwords').'.expire');
    $saudacao = 'Olá, '.$this->name.'! :)';
    
    return (new MailMessage)
        ->subject('Atualização de senha')
        ->greeting($saudacao)
        ->line('Esqueceu a senha? Sem problemas, vamos resolver isso!')
        ->action('Clique aqui para modificar a senha', $url)
        ->line('O link acima expira em '.$minutos.' minutos!')
        ->line('Caso você não tenha requisitado a alteração de senha, então nenhuma ação é necessária.')
        ->salutation('Até breve!');
}
~~~

- em `vendor/laravel/framework/src/Illuminate/Notifications/resources/views/email.blade.php`:

~~~php
@lang(
    "Caso você tenha problemas com o botão acima, por favor copie e cole o link abauxo em seu navegador:".
    'into your web browser:',
    [
        'actionText' => $actionText,
    ]
) 
~~~

<h2 id="topico7">7. Ajustando as políticas de senha no reset</h2>

- `app/Http/Controllers/Auth/ResetPasswordController.php` implementa o método **reset, em ResetsPasswords**, localizado em `vendor/laravel/ui/auth-backend/ResetsPassword.php`:

~~~php
protected function rules()
{
    return [
        'token' => 'required',
        'email' => 'required|email',
        'password' => ['required', 'confirmed', Rules\Password::defaults()],
    ];
}
~~~

- no caso do laravel 13, acessar `app/Providers/AppServiceProvider.php`:

~~~php
use Illuminate\Validation\Rules\Password;

class AppServiceProvider extends ServiceProvider
{
    public function boot(): void
    {
        Password::defaults(function () {
            return Password::min(4);
        });
    }
}
~~~

- **OU** podemos sobrescrever o método em `app/Http/Controllers/Auth/ResetPasswordController.php`:

~~~php
protected function rules() {
    return [
        'token' => 'required',
        'email' => 'required|email',
        'password' => 'required|confirmed|min:4'
    ];
}
~~~

<h2 id="topico8">8. Verificação de e-mail (MustVerifyEmail)</h2>

- esse recurso é importante paras evitar que pessoas mal intencionadas possam se cadastrar na aplicação com emails inválidos ou de terceiros. 
- em `app/Models/User.php` possuímos uma interface chamada **MustVerifyEmail**, a qual devemos implementar na nossa classe:

~~~php
use Illuminate\Contracts\Auth\MustVerifyEmail;

#[Fillable(['name', 'email', 'password'])]
#[Hidden(['password', 'remember_token'])]
class User extends Authenticatable implements MustVerifyEmail
~~~

- na sequência, em `routes/web.php`:

~~~php
Auth::routes(['verify' => true]);
~~~

- para proteger as rotas, de modo que só consiga acessar após a verificação do email, em `routes/web.php`:

~~~php
Auth::routes(['verify' => true]);

Route::get('/home', [App\Http\Controllers\HomeController::class, 'index'])
    ->name('home')
    ->middleware(['auth', 'verified']);

Route::resource('tarefa', TarefaController::class)
    ->middleware(['auth', 'verified']);
    
Route::get('/mensagem-teste', function() {
    // return new MensagemTesteMail();
    Mail::to('cursolaravelvue123@gmail.com')->send(new MensagemTesteMail());
    return 'E-mail enviado com sucesso!';
});
~~~

- agora, após o cadastro, aparecerá a mensagem: "Verify Your Email Address - Before proceeding, please check your email for a verification link. If you did not receive the email, click here to request another."

<h2 id="topico10">10. Customizando a mensagem de verificação de e-mail</h2>

- criar uma classe de notificação que será utilizada no método que fará o desvio no fluxo da aplicação, para que o email seja enviado de modo curtomizado.
- na linha de comando, executar:

~~~bash
php artisan make:notification VerificarEmailNotification
~~~

- em `app/Models/User.php`:

~~~php
use App\Notifications\VerificarEmailNotification;

#[Override]
public function sendEmailVerificationNotification()
{
    $this->notify(new VerificarEmailNotification);
}
~~~

- em `app/Notifications/VerificarEmailNotification.php`:

~~~php
class VerificarEmailNotification extends Notification
{
    public $name;

    public function __construct($name)
    {
        $this->name = $name;
    }

    protected function buildMailMessage($url)
    {
        return (new MailMessage)
            ->subject('Confirmação de e-mail')
            ->greeting('Olá '.$this->name)
            ->line('Clique no botão abaixo para validar seu e-mail.')
            ->action('Clique aqui para validar', $url)
            ->line('Caso não tenha se cadastrado em nosso sistema, apenas desconsidere essa mensagem.');
    }
}
~~~

<h2 id="topico13">13. Associando o usuário a tarefa</h2>

- vamos fazer um desenvolvimento incrementar no BD para que as tarefas estejam relacionadas ao usuário que as criou.
- na linha de comando, executar: `php artisan make:migration alter_table_tarefas_relacionamento_users` e, na migration:

~~~php
return new class extends Migration
{
    public function up(): void
    {
        Schema::table('tarefas', function(Blueprint $table) {
            $table->unsignedBigInteger('user_id')->nullable()->after('id');
            $table->foreign('user_id')->references('id')->on('users');
        });
    }

    public function down(): void
    {
        Schema::table('tarefas', function(Blueprint $table) {
            $table->dropForeign('tarefas_user_id_foreign');
            $table->dropColumn('user_id');
        });
    }
};
~~~

- executar `php artisan migrate`.
- em `app/Http/Controllers/TarefaController.php`:

~~~php
public function store(Request $request)
{
    $dados = $request->all('tarefa', 'data_limite_conclusao');
    $dados['user_id'] = Auth::user()->id;
    $tarefa = Tarefa::create($dados);
    $destinatario = Auth::user()->email;
    Mail::to($destinatario)->send(new NovaTarefaMail($tarefa));
    return redirect()->route('tarefa.show', ['tarefa' => $tarefa->id]);
}
~~~
