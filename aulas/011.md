<h2 id="topico1">1. Iniciando o projeto Controle de Tarefas</h2>

- na linha de comando, executar `composer create-project --prefer-dist laravel/laravel app_controle_tarefas`, e depois `php artisan server`

<h2 id="topico2">2. [LINUX] Instalando o NodeJS e o NPM</h2>

- são recursos importantes pois nessa seção trabalharemos com o recurso de pacote UI do Laravel.
    - `node.js` é uma plataforma de execução de código javascript; através dele nós temos condições de criar backends de aplicações web utilizando a linguagem de programação javascript. Também permite criar aplicações frontend baseadas no framework, como angular, react e vue, que são frameworks frontend muito utilizados no mercado.
    - `npm` é o gerenciador de pacotes do node. Ele é para o javascript o que o composer é para o php. Por meio do npm temos condições de adicionar dependências aos nossos projetos.

- para fazer a instalação, acessar o site do [Node.js](https://nodejs.org).
- baixar a versão LTS.

~~~bash
# Download and install nvm:
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.7/install.sh | bash
# in lieu of restarting the shell
\. "$HOME/.nvm/nvm.sh"
# Download and install Node.js:
nvm install 24
# Verify the Node.js version:
node -v # Should print "v24.19.0".
# Verify npm version:
npm -v # Should print "11.17.0".
~~~

~~~bash
nvm install 24
nvm alias default 24

node -v
npm -v
which node
~~~

- o npm é instalado durante esse procedimento.

<h2 id="topico4">4. Entendendo o pacote UI e iniciando a autenticação WEB nativa do Laravel</h2>

### a) Entendendo o pacote UI:

- esse pacote permite iniciar projetos com predefinições de frontend, que podem ser baseadas nos frameworks JS react ou vue e no kit css bootstrap.
- podemos ainda, por meio das APIs, trabalhar com outros frameworks, como angular.
- na linha de comando, utilizar:

~~~bash
php artisan ui <front_end> [auth]
php artisan ui bootstrap --auth
~~~

- esse comando produz um `Scaffold` (esqueleto) de uma aplicação: uma aplicação inicial, para que a partir dela possamos desenvolver o restante da aplicação.
- são insluídos diversos arquivos, como:
    - package.json: dependências javascript
    - routes/web.php: adiciona rotas de autenticação
    - app/Http/Controllers -> Auth
        - ConfirmPasswordController.php
        - ForgotPasswordController.php
        - LoginController.php
        - RegisterController.php
        - ResetController.php
        - VerificationController.php
    - app/models/User.php
    - public
        - css -> app.css
        - js -> app.js
    - resources/views 
        - home.blade.php
        - auth
            - login.blaade.php
            - register.blade.php
            - verify.blade.php
            - passwords (confirm.blade.php, email.blade.php. reset.blade.php)
        - layouts
            - app.blade.php
    - resources/js/bootstrap.js: pré-definições do JS de acordo com o frontend selecionado

### b) Preparando o projeto app_controle_tarefas:

- executar o comando:

~~~bash
php artisan ui bootstrap --auth
npm install
npm run dev
~~~

<h2 id="topico7">7. Validando campos de confirmação (confirmed) e mudando regras de senhas</h2>

- em `app/Http/Controllers/Auth/RegisterController.php`, modificaremos a validação de password:

~~~php
protected function validator(array $data)
{
    return Validator::make($data, [
        'name' => ['required', 'string', 'max:255'],
        'email' => ['required', 'string', 'email', 'max:255', 'unique:users'],
        'password' => ['required', 'string', 'min:4', 'confirmed'],
    ]);
}
~~~

- a **validação confirmed** relaciona um outro campo do form com o campo que está sendo validado (no caso, campos com names 'password' e 'password_confirmation' - sendo que o '_confirmation' é introduzido automaticamente).

<h2 id="topico8">8. Entendendo como a rota Home está protegida</h2>

- dentro da nossa aplicação há a **rota /home**, a qual requer que o processo de autenticação seja realizado para que possamos acessá-la.
    - caso tentemos acessar, somos redirecionados à tela de login.
    - ou seja, é uma rota protegida.

- em `app/Http/Controllers/HomeController.php`, temos:

~~~php
public function __construct()
{
    $this->middleware('auth');
}
~~~

- ou seja, na construção desse controlador, quando ele é instanciado pelo framework Laravel, ele carrega o **middleware('auth')**, instrução que aplica as regras de validação por meio da superglobal session do php.
- o **moddleware('auth')** está definido no arquivo **Kernel.php**, no caso do prof (versão mais antiga), e no meu caso, em **bootstrap/app.php**.
    - a documentação informa que aliases personalizados são registrados com $middleware->alias() dentro do bootstrap/app.php.
    - na lista do professor tem: auth, auth.basic, cache.headers, can, guest, password.confirm, signed, throttle verified.
    - porém não há necessidade de cadastrar nenhum desses, pois no Laravel 13 eles já estão disponíveis.

<h2 id="topico10">10. Implementando o middleware auth</h2>

- em `routes/web.php`, implementar o mapeamento de rotas para o Controlador:

~~~php
Route::resource('tarefa', TarefaController::class);
~~~

- em `app/Http/Controllers/TarefaController.php`:

~~~php
public function index()
{
    return 'Chegamos até aqui';
}
~~~

- para proteger essa rota, há duas possibilidades:

1. em `app/Http/Controllers/TarefaController.php`:

~~~php
public function __construct()
{
    $this->middleware('auth');
}
~~~

2. em `routes/web.php`:

~~~php
Route::resource('tarefa', TarefaController::class)->middleware('auth');
~~~

<h2 id="topico11">11. Verificando se o usuário está logado dentro dos métodos do Controller</h2>

- para verificar se o usuário está autenticado, podemos utilizar o método em `app/Http/Controllers/TarefaController.php`:

~~~php
public function index()
{
    if(auth()->check()) {
        return 'Você ESTÁ logado no sistema! :)';
    } else {
        return 'Você não está logado no sistema! :(';
    }
}
~~~

- podemos, por meio do **helper auth()**, recuperar informações relativas ao usuário logado (atributos da tabela users). 

~~~php
public function __construct()
{
    // $this->middleware('auth');
}

public function index()
{
    if(auth()->check()) {
        $id = auth()->user()->id;
        $name = auth()->user()->name;
        $email = auth()->user()->email;

        return "ID: $id | Nome: $name | Email: $email";
    } else {
        return 'Você não está logado no sistema! :(';
    }
}
~~~

- também podemos utilizar outra sintaxe, por meio da **classe Auth** e da chamada dos seus respectivos métodos estáticos; exemplo:

~~~php
use Illuminate\Support\Facades\Auth;

class TarefaController extends Controller
{
    public function __construct()
    {
        // $this->middleware('auth');
    }


    public function index()
    {
        if(Auth::check()) {
            $id = Auth::user()->id;
            $name = Auth::user()->name;
            $email = Auth::user()->email;

            return "ID: $id | Nome: $name | Email: $email";
        } else {
            return 'Você não está logado no sistema! :(';
        }
    }
// ...
}
~~~

- se mantiver a autenticação no construto, garantirá que todo o controller estará protegido, e pode, ainda assim, recuperar as informações, como em:

~~~php
public function __construct()
{
    $this->middleware('auth');
}

public function index()
{
    $id = Auth::user()->id;
    $name = Auth::user()->name;
    $email = Auth::user()->email;

    return "ID: $id | Nome: $name | Email: $email";
}
~~~
