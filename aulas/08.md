<h2 id="topico1">1. Introdução aos Middlewares</h2>

- são camadas de software implementadas entre aplicações distintas.
- funcionam como um intermediador de comunicação, ou seja, de entrada e saída entre aplicações distintas.
- no contexto web, atuam na interceptação de requisições http feitas por browsers, e também na manipulação da resposta que é dada pela aplicação a esses mesmos browsers.
    - quando estamos falando de middlewares que atuam na **requisição** (Request http), a ideia é capturar a requisição antes que ela seja submetida para o núcleo da aplicação, permitindo a realização de inúmeras ações (como verificar se o usuário está ou não autenticado).
    - quando estamos falando de middlewares que atuam na **resposta** (Response http), a ideia é manipular essa resposta para um propósito específico (como para padronização de cabeçalho quando estamos trabalhando com aplicações CORS - Cross-Origin Resource Sharing - compartilhamento de recursos com origens diferentes).

<h2 id="topico2">2. Criando meu primeiro middleware</h2>

- [Documentação referente a Middlewares](https://laravel.com/docs/13.x/middleware).

> Para criar o primeiro Middleware, utilizar a instrução `php artisan make:middleware LogAcessoMiddleware`.

- acessar a Middleware criada em: `app` > `Http` > `Middleware` > `LogAcessoMiddleware`:

~~~php
<?php

namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\Response;

class LogAcessoMiddleware
{
    /**
     * Handle an incoming request.
     *
     * @param  Closure(Request): (Response)  $next
     */
    public function handle(Request $request, Closure $next): Response
    {
        return $next($request);
    }
}
~~~

- para ativar o Middleware, precisamos atribui-lo a rotas ou controladores. Uma vez que eçe é utilizado, execurará a função handle().

- Para **atribuir o middleware criado a uma rota**:
    - em `routes` > `web.php`:

~~~php
use \App\Http\Middleware\LogAcessoMiddleware;

Route::middleware(LogAcessoMiddleware::class)
    -> get('/', [\App\Http\Controllers\PrincipalController::class, 'principal'])
    -> name('site.index');
Route::get('/contato', [\App\Http\Controllers\ContatoController::class,'contato'])
    -> name('site.contato')
    -> middleware(LogAcessoMiddleware::class);
~~~

- em `app` > `Http` > `Middleware` > `LogAcessoMiddleware`:

~~~php
<?php

namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\Response;

class LogAcessoMiddleware
{
    /**
     * Handle an incoming request.
     *
     * @param  Closure(Request): (Response)  $next
     */
    public function handle(Request $request, Closure $next): Response
    {
        // return $next($request);
        return Response('Chegamos no middleware e finalizamos no próprio middleware!');
    }
}
~~~

<h2 id="topico3">3. Criando o model LogAcesso e sua migration</h2>

- o objetivo da aula será implementar um novo model chamado LogAcesso e uma migration relacionada a esse novo model para que a mensagem retornada no método handle() do middleware LogAcessoMiddleware seja persistida no BD, o que ajuda a criar um cenario mais completo para testes.

- executar o comando `php artisan make:model LogAcesso -m`.
- na migration ``:

~~~php
public function up(): void
{
    Schema::create('log_acessos', function (Blueprint $table) {
        $table->id();
        $table->string('log', length: 200);
        $table->timestamps();
    });
}
~~~

- executar o comando `php artisan migrate`.
- no workbench:

~~~sql
use sg;
select * from log_acessos;
~~~

- em `app` > `Models` > `LogAcesso.php`:

~~~php
<?php
namespace App\Models;

use Illuminate\Database\Eloquent\Model;
use \App\Models\LogAcesso;

class LogAcesso extends Model
{
    protected $fillable = ['log'];
}
~~~

- em `app` > `Http` > `Middleware` > `LogAcessoMiddleware`:

~~~php
use \App\Models\LogAcesso;


class LogAcessoMiddleware
{
    public function handle(Request $request, Closure $next): Response
    {
        // return $next($request);
        LogAcesso::create(['log' => 'IP xyz requisitou a rota abcd']);
        return Response('Chegamos no middleware e finalizamos no próprio middleware!');
    }
}
~~~

- no workbench, executando o comando `select * from log_acessos;`, verificamos o registro na tabela.

> print_r($request) não funciona na middleware, apenas dd($request).

- para obter as informações de IP (recuperado através do `atributo server` de $request, `parâmetro REMOTE_ADDR`).
- para recuperar a rota, utilizar os o `atributo requestUri`.

~~~php
use Closure;
use \App\Models\LogAcesso;
use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\Response;

class LogAcessoMiddleware
{
    public function handle(Request $request, Closure $next): Response
    {
        $ip = $request->server->get('REMOTE_ADDR');
        $rota = $request->getRequestUri();
        LogAcesso::create(['log' => "IP $ip requisitou a rota $rota"]);
        return Response('Chegamos no middleware e finalizamos no próprio middleware!');
    }
}
~~~

<h2 id="topico4">4. Implementando middlewares no método construtor dos controllers</h2>

- na aula anterior, implementamos middlewares diretamente nas rotas; agora aprenderemos como fazer a chamada dos middlewares diretamente nos controladores, em seus métodos constructor().
- em `SobreNosController.php`:

~~~php
<?php

namespace App\Http\Controllers;

use Illuminate\Http\Request;
use App\Http\Middleware\LogAcessoMiddleware;

class SobreNosController extends Controller
{
    public function __construct() {
        $this->middleware(LogAcessoMiddleware::class);
    }

    public function sobreNos() {
        return view('site.sobre-nos');
    }
}
~~~ 

- porém, no **Laravel 11/13 a forma de registrar middlewares em controllers mudou**!
    - a forma mais recomendada no Laravel 13 é `aplicar na rota`, como abaixo, em `web.php`:

~~~php
<?php

use Illuminate\Support\Facades\Route;
use \App\Http\Middleware\LogAcessoMiddleware;

Route::middleware(LogAcessoMiddleware::class)
    -> get('/', [\App\Http\Controllers\PrincipalController::class, 'principal'])
    -> name('site.index');
Route::middleware(LogAcessoMiddleware::class)
    ->get('/sobre-nos', [\App\Http\Controllers\SobreNosController::class, 'sobreNos']) 
    -> name('site.sobrenos');
Route::middleware(LogAcessoMiddleware::class)
    ->get('/contato', [\App\Http\Controllers\ContatoController::class,'contato']) 
    -> name('site.contato');
~~~

<h2 id="topico5">5. Implementando um middleware para todas as rotas</h2>

- a `Classe Kernel.php`, localizada dentro dos repositórios Http e App, é responsável por iniciar diversos middlewares, e defini-los para grupos de rotas dentro da aplicação.
- há basicamente **2 tipos de rotas** dentro da aplicação: web e de API.
- no shell:

~~~
cd Documentos/estudando/webAvancadoSantAna/code/app_super_gestao
php artisan route:list
~~~

- no arquivo `Kernel.php` haviam várias rotas pré-definidas; porém, no Laravel 11 e 13, o app/Http/Kernel.php não existe mais em uma instalação padrão.

<div align="center">

Laravel 7 | Laravel 13
-----------|---------------
app/Http/Kernel.php	| bootstrap/app.php
$this->middleware() no controller | Preferencialmente middleware na rota ou HasMiddleware
Registro de aliases no Kernel | Registro em bootstrap/app.php
Estrutura de inicialização | Simplificada com Application::configure()

</div>


- já no diretório `bootstrap`, arquivo `app.php`:

~~~php
<?php

use Illuminate\Foundation\Application;
use Illuminate\Foundation\Configuration\Exceptions;
use Illuminate\Foundation\Configuration\Middleware;
use Illuminate\Http\Request;

return Application::configure(basePath: dirname(__DIR__))
    ->withRouting(
        web: __DIR__.'/../routes/web.php',
        commands: __DIR__.'/../routes/console.php',
        health: '/up',
    )
    ->withMiddleware(function (Middleware $middleware): void {
        //
    })
    ->withExceptions(function (Exceptions $exceptions): void {
        $exceptions->shouldRenderJsonWhen(
            fn (Request $request) => $request->is('api/*'),
        );
    })->create();
~~~

- em `web.php`, retirar as middlewares:

~~~php
<?php

use Illuminate\Support\Facades\Route;

Route::get('/teste/{p1}/{p2}', [\App\Http\Controllers\TesteController::class, 'teste']) -> name ('teste');

~~~

- ajustando bootstrap > `app.php`:

~~~php
<?php
~~~

~~~php
->withMiddleware(function (Middleware $middleware): void {

    /* $middleware->web(append: [
        LogAcessoMiddleware::class,
    ]);*/

    $middleware->alias([
        'log.acesso' => LogAcessoMiddleware::class,

~~~

- já em `web.php`:

~~~php
Route::get('/', [\App\Http\Controllers\PrincipalController::class, 'principal'])->name('site.index')->middleware('log.acesso');
~~~

- o professor executou em `SobreNosController.php`:

~~~php
public function __construct() {
    $this->middleware('log.acesso');
}
~~~

- porém, no Laravel 11/12/13, dentro do construtor do controller não é mais suportado da mesma forma que nas versões anteriores, por isso o erro "Call to undefined method App\Http\Controllers\SobreNosController::middleware()".
- o mais indicado é aplicar o middleware diretamente na rota:

~~~php
Route::get('/sobre-nos', [SobreNosController::class, 'sobreNos'])
    ->middleware('log.acesso')
    ->name('site.sobrenos');
~~~

- ou se quiser proteger várias rotas:

~~~php
Route::middleware('log.acesso')->group(function () {
    Route::get('/sobre-nos', [SobreNosController::class, 'sobreNos'])
        ->name('site.sobrenos');

    Route::get('/contato', [ContatoController::class, 'contato'])
        ->name('site.contato');
});
~~~

<h2 id="topico7">7. Encadeamento de middlewares (criando um middleware de autenticação)</h2>

- no terminal, executar o comando `php artisan make:middleware AutenticacaoMiddleware`.
- em `app/Http/Middlewares/AutenticacaoMiddleware.php`:

~~~php
<?php

namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\Response;

class AutenticacaoMiddleware
{
    public function handle(Request $request, Closure $next): Response
    {
        //return $next($request);
        return Response('Acesso negado! A rota exige autenticação!!!');
    }
}
~~~

- as rotas dentro do **grupo '/app'**, em `routes/web.php`, deveráo ser protegidas, e só possível o acesso a usuários autenticados. Portanto, vamos dar um apelido para a rota, em `bootstrap/app.php`.

~~~php
<?php

use App\Http\Middleware\LogAcessoMiddleware;
use App\Http\Middleware\AutenticacaoMiddleware;

use Illuminate\Foundation\Application;
use Illuminate\Foundation\Configuration\Exceptions;
use Illuminate\Foundation\Configuration\Middleware;
use Illuminate\Http\Request;

return Application::configure(basePath: dirname(__DIR__))
    ->withRouting(
        web: __DIR__.'/../routes/web.php',
        commands: __DIR__.'/../routes/console.php',
        health: '/up',
    )
    ->withMiddleware(function (Middleware $middleware): void {
        /*$middleware->web(append: [
            LogAcessoMiddleware::class,
        ]);*/
        $middleware->alias([
            'log.acesso' => LogAcessoMiddleware::class,
            'autenticacao' => AutenticacaoMiddleware::class
        ]);

    })
    ->withExceptions(function (Exceptions $exceptions): void {
        $exceptions->shouldRenderJsonWhen(
            fn (Request $request) => $request->is('api/*'),
        );
    })->create();
~~~

- em `routes/web.php`:

~~~php
Route::prefix('/app') -> group(function() {
    Route::middleware('autenticacao')
        ->get('/clientes', function() {return 'Clientes';}) 
        -> name('app.clientes');


    Route::get('/fornecedores', [\App\Http\Controllers\FornecedoresController::class, 'index']) -> name('app.fornecedores');
    Route::get('/produtos', function() {return 'Produtos';}) -> name('app.produtos');
});
~~~

- porém, em `app/Http/Middlewares/LogAcessoMiddleware.php`, o comando **//return $next($request);** encontra-se comentado, fazendo com que o método $next() não seja chamado, e consequentemente não encaminhando a requisição para frente - vai morrer no primeiro middleware (o log.acesso), para fazer com que a requisição passe por log/acesso e vá até o middleware Autenticação, devemos:

~~~php
class LogAcessoMiddleware
{
    public function handle(Request $request, Closure $next): Response
    {
        $ip = $request->server->get('REMOTE_ADDR');
        $rota = $request->getRequestUri();
        LogAcesso::create(['log' => "IP $ip requisitou a rota $rota"]);
        
        return $next($request);
    }
}
~~~

- Exemplo de autenticação em `app/Http/Middlewares/AutenticacaoMiddleware.php`:

~~~php
class AutenticacaoMiddleware
{
    public function handle(Request $request, Closure $next): Response
    {
        // verifica se o usuário possui acesso à rota:
            if(true) {
            return $next($request);
            } else {
            return Response('Acesso negado! A rota exige autenticação!!!');
            }
    }
}
~~~

- em `routes/web.php`:

~~~php
Route::prefix('/app') -> group(function() {
    Route::middleware('log.acesso', 'autenticacao')
        -> get('/clientes', function() {return 'Clientes';}) 
        -> name('app.clientes');
    
    Route::middleware('log.acesso', 'autenticacao')
        -> get('/fornecedores', [\App\Http\Controllers\FornecedoresController::class, 'index']) 
        -> name('app.fornecedores');

    Route::middleware('log.acesso', 'autenticacao')
        -> get('/produtos', function() {return 'Produtos';}) 
        -> name('app.produtos');
});
~~~

- em `bootstrap/app.php`:

~~~php
return Application::configure(basePath: dirname(__DIR__))
    ->withMiddleware(function (Middleware $middleware): void {
        $middleware->web(append: [
            LogAcessoMiddleware::class,
        ]);
        $middleware->alias([
            'log.acesso' => LogAcessoMiddleware::class,
            'autenticacao' => AutenticacaoMiddleware::class
        ]);
    })
~~~

- em `routes/web.php`:

~~~php
Route::prefix('/app') -> group(function() {
    Route::middleware('autenticacao')
        -> get('/clientes', function() {return 'Clientes';}) 
        -> name('app.clientes');
    
    Route::middleware('autenticacao')
        -> get('/fornecedores', [\App\Http\Controllers\FornecedoresController::class, 'index']) 
        -> name('app.fornecedores');

    Route::middleware('autenticacao')
        -> get('/produtos', function() {return 'Produtos';}) 
        -> name('app.produtos');
});
~~~

<h2 id="topico9">9. Passando parâmetros para o middleware</h2>
